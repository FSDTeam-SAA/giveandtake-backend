1. JOB POST CREDITS WITHOUT AN EXPIRY DATE
- Company and recruiter packages use one-time purchased job post credits.
- Purchased credits have no monthly or yearly usage deadline.
- A buyer can use one credit today and another six months later.
- Buying another package adds to the remaining credit balance.
- Usage is recorded against the purchase. Deleting a job does not restore
  the credit or remove its refund deduction for posts recorded after rollout.
- Unlimited packages use a true unlimited allocation.

- Purchase buttons connect to the existing payment flow.

3. REFUND RESTRICTIONS
- Company and recruiter refund requests are rejected after 30 days from
  the original payment timestamp.
- Each job posted from the purchase is deducted at exactly $99.99.
- The existing administration fee is retained: 10% of the remaining
  balance AFTER job-post deductions, rounded to cents.
- No refund is issued when no positive refundable balance remains.
- Refunded purchases cannot provide further job credits.
- Concurrent refund requests and credit spending are guarded by a payment
  lock; credit consumption and job creation share a database transaction.

  Example: Basic Plan purchased for $195.99, with one job used:
  Job deduction: $99.99
  Remaining balance: $96.00
  Administration fee: $9.60
  Refund: $86.40, provided the request is within 30 days.

6. REQUIRED VPS DEPLOYMENT STEPS
Push changes from evpitch-backend, evpitch-frontend and evpitch-admin,
including new source files, tests and the migration script.
Do not commit the backend .env file; set the environment value on the VPS.

During a maintenance window:
1. Back up the subscription-plan and payment collections. Pause purchases,
   job creation and scheduled expiry tasks.
2. Pull the updated code and install dependencies using the existing
   deployment process. Build the backend and both websites. Check for
   build failures before switching traffic to the new versions.
3. Set JOB_POST_PAYWALL_ENABLED=true in the VPS backend environment.
   This setting was enabled locally but must also be enabled on the VPS.
4. From the backend directory, run:
     npm run migrate-job-packages
   Review the preview, then apply it:
     npm run migrate-job-packages -- --apply
   If only compiled production files are installed, after npm run build use:
     node dist/scripts/migrate-job-packages.js
     node dist/scripts/migrate-job-packages.js --apply
5. Restart the backend and both websites with the updated environment using
   the existing VPS process manager. Keep the backend, websites and database
   migration coordinated, then resume scheduled tasks and traffic.
6. Check both pricing pages, admin Plan management and Payment Details.
   Complete a staging checkout, credit-spending and refund smoke test.

MongoDB must support transactions, such as Atlas or a replica set.

EXISTING DATA CONSIDERATIONS
- Existing purchase amounts and timestamps are preserved by the migration.
- Already-deactivated purchases are not automatically reactivated because
  the existing data does not distinguish expiry from manual deactivation.
- Historical usage can only be reconstructed from remaining jobs linked to
  a purchase. Previously deleted or unlinked jobs need reconciliation from
  an audit source or backup. The new durable counter prevents this loss
  for future posts.
